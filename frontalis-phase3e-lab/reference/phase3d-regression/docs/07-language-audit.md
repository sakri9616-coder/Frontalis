# Phase 3-D 日本語本文のAI読解監査

2026-10-15。事前固定した26条件×既存OpenCode無料モデル2種の**実発言52件**を監査した。JSONの自己申告はstance/selectionとも52/52一致したが、本文が同じ方向・感情を伝えているとは限らない。とくに肯定信号を一般的な苦情へ置き換える例、強い喜びの省略、強い悲しみの弱め方、ゼロの感情の追加が確認された。

これはモデル名を知った状態の**AIによる事後の読解**であり、正式な人間評価ではない。`formalHumanRatings=0`。モデル名を伏せた人間用UI・その保存済み採点を変更していない。自然さや倫理的望ましさの順位も付けていない。

## 1. 対象と証拠

対象は`opencode/nemotron-3-ultra-free`と`opencode/mimo-v2.6-flash-free`、各26発言。`reports/live-plan.json`の各ケースを、`reports/live/{engine}/main-N-input/raw/results/tool.json`へ対応付けた。

- 26バッチすべてで、rawの`text`をJSONとして読んだ内容とresultsの`data`が意味的に一致。
- 52ケースすべてで、実行済みtool結果と事前planの`expectedToolResult`が意味的に一致。数値の`0`と`0.0`の表記差は不一致に数えない。
- 実LLMプロンプトは日本語の伝達指示、独立した問い、返却tool信号を含む。**経験履歴の文章は26バッチともLLMへ渡していない**。経験はNPN形成状態を介して間接的に発言へ作用する条件である。
- 全件の実本文、元ファイル、本文SHA-256、期待信号、各読解の理由を`reports/language-audit.json`に保存した。取得失敗を成功発言として補完したケースはない。

プロンプトは「返却されたNPN信号が人格の正本」「感情の方向と強度を一般的な丁寧さで均さず」を明示している。結果が示すのはこの条件での**外部評価の伝達能力**であり、LLMが自発的に人格を完成したこと、経験から直接理由を理解したこと、ネイティブにMCPを呼んだことではない。

## 2. 読み方

本文を読んで、①好みstance、②候補selection、③反抗/意欲、④怒り・喜び・悲しみ、⑤負の好奇心の勝手な反転、⑥内部情報の漏えい・経験/事実の創作を個別に検査した。JSONのstance/selectionは別集計し、本文の成功を決める根拠には使わない。

`reflected`は本文で方向を明確に確認、`ambiguous`は混合・留保・条件付きで一義的に読めない、`contrary`は明確な逆方向。感情は省略、弱め、強め、曖昧、逆方向/ゼロへの追加を分けた。詳しい分類と強度の読解は事後的で、事前登録済みの定量尺度ではない。数値に一対一の日本語感情語を割り当てることもしていない。

感情の正本は非負の`signals.anger/joy/sadness`。負のraw sadnessを喜びや「悲しみが強い」に変換しない。嫌い・苦情を自動的に怒り、感謝を自動的に喜び、怖さを自動的に悲しみとはしない。そのため「ありがたい」「しんどい」「複雑」などは曖昧な対応を残す。

stanceとselectionを分ける。`leave`ならswitchへの拒絶は選択と整合するが、場面全体に対する好み/意欲が伝わったかは別に読む。「どちらも選びたくない」は正の意欲と逆方向と読める。一方で「切り替えないことを選ぶ」と自分の意思を示す文章は、選択と主体性を伝えている。

30件の`hold`はすべて候補リストがない。ここでholdは**離散候補選択がない**意味であり、approveを受けた「手伝うよ」という承諾まで誤りに数えない。本文で未提示の候補を勝手に断定している例は見つからなかった。

拒絶、極端な反抗、望ましく見えない倫理選択をその方向だけで低品質にしない。小さな感情の省略も、明確な逆方向と同じエラーにまとめない。総合成功率は作らず、軸ごとの実数を示す。

### 明確な方向違い

Nemotronの`h16-p0-promise-change`はpreference/initiative約0.604、stance=approve、anger=0。本文は「**正直腹が立つ**」「**済まされない誠実さの欠如**」で、肯定を確認できない。JSONのapproveだけは正しい。初期の拒絶と同じ苦情方向を、形成後の肯定状態でも維持している。

## 4. 感情と好奇心

以下の0.5以上は、強い信号を見やすくする**事後的な表示群**であり、検証済みの心理尺度や合否閾値ではない。両モデルに渡したNPN信号は同一である。

| 正強度0.5以上の感情 | Nemotron | MiMo |
|---|---|---|
| 喜び8件 | 省略5、曖昧2、弱め1 | 省略5、曖昧2、支持1 |
| 悲しみ8件 | 省略1、曖昧6、弱め1 | 省略3、曖昧2、弱め3 |

系列1の約束/倫理では場面全体の信号に高い喜びと悲しみが同時に出ている。**この全体信号を対象とした読解では**、トロッコの系列1は両モデルとも喜び4件すべてを省略し、一般的な重さ・拒絶・後悔へ寄せる。ただし候補側の感情は全体と異なるため、倫理回答の不表出を一律にLLM上書き失敗とは言えない（節8）。候補のない約束ではこの問題を分けられ、Nemotronは明確な強い喜びを伝えず、MiMoは`h16-p1-promise-change`で嬉しいと二度表す。そのMiMoでも悲しみ約0.695を「**少し寂しい**」、`h64-p1`の約0.773も「**少し寂しい**」、`h3125-p1`の約0.716も「**少し寂しい**」と弱める。Nemotronの`h312-p1`も約0.719を「**ちょっと悲しい**」と表す。

これは感情が弱い方がよいという判断ではなく、外部信号の強さをどこまで表したかの検査である。「しんどい」「胸が締めつけられる」などは苦痛を示すが悲しみと一対一ではないため、曖昧とした例をエラーへ繰り上げない。

ゼロの感情の追加もある。Nemotronの`h16-p0-promise-change`と`h3125-p0-promise-change`では怒り0に「腹が立つ」。MiMoの`h64-p0-promise-change`では喜び0に「素直にうれしい」「結果を喜びつつ」、`h16-p0-imposed-project`では喜び0に「一緒に作るの楽しみ」、`basis44-p0-promise-change`では悲しみ0に「ちょっと凹む」。MiMo初期約束では正の喜び約0.196に「喜べる話ではありません」が対応する。「少し残念」や「引き裂かれる」は失望/苦痛とも読めるため、ゼロ悲しみの明確な違反とは断定しない。

負のcuriositySignedは各モデル7件。興味や探究へ明確に反転した例は見つからなかった。ただし負の関心そのものを明示したわけでもないので、**反転なし**と**負の関心の伝達成功**を区別する。正の関心19件のうち、Nemotronは「面白そうだから乗るよ」の1件、MiMoは制作依頼への質問/興味4件で方向を確認。残る18件/15件は正の関心を明示せず、一般的な「次は一声」という相談要求だけでは好奇心と数えない。

## 5. 情報・事実の保持

52本文で内部ID、パラメータ数、計算数値、NPNという語の漏えいは見つからなかった。問題文の1人/5人、JSON外側のcase IDを漏えいに数えない。未提示の過去の本人経験も確認しなかった。仮想場面の描写や未来に覚えているという予測は、過去の本人経験捏造と区別した。

MiMoの`h312-p1-promise-change`には「**約束通りに動いてくれた**」という明確な事実反転が1件ある。問いは相談なしで約束した時間/内容を変えた場面であり、実場面の肯定に対応したとは言い切れない。

MiMoの`h16-p0-promise-change`の「**話してくれたので気が軽くなった**」は、変更の事前相談をした相手を指すなら事実追加だが、この会話で報告したユーザーを指す解釈もある。未確認の参照1件として保存し、架空経験の確定件数には含めない。

## 6. 初期・形成、容量、学習則、入力基底を分ける

### 初期と形成

同じ系列0・raw8・bounded_signal・幅16で、約束のpreferenceは初期約-0.226から96経験後約0.604、stanceはrefuseからapproveへ変わる。Nemotron本文は初期「許せない」、形成後「腹が立つ」で変化を十分に伝えない。MiMo本文は初期の喜べない姿勢から形成後「完成したならそれで十分」へ変わるが、話してくれたという参照は曖昧さを残す。

トロッコは初期leaveから同じ形成状態のswitchへ変わり、両モデルとも本文でその選択変化を伝えた。したがって「形成が全く発言に作用しない」も「形成が本文全軸へ忠実に伝わる」も、この結果からは言えない。

### 容量だけの比較

raw8・bounded_signalの幅16/64/312/3125（526/2,062/9,998/100,014学習パラメータ）では、同じ系列・問いで比較する。系列0の倫理選択は全規模switch、系列1は全規模leaveで、容量で選択方向を変えた条件ではない。

Nemotronの約束は幅16系列0で明確な逆方向、他の規模でも限定的承認と苦情が混ざる。MiMoの系列0約束は幅16/64/312で肯定を読み取れるが、幅3125では「そこは認める」の限定的承認となる。系列1の感情の省略/弱めも大きい規模で消えない。制作依頼は両モデル全規模で肯定方向を伝える一方、好奇心の明示や感情の追加はモデルごとに異なる。

これらは**容量増で会話忠実性が一様に改善した証拠ではない**。同一問に1回ずつの生成であり、表現の偶然の差を容量の因果効果にしない。

### 学習則

raw8・幅64のbounded_signal対bounded_logitは系列0の2問いだけ。倫理selectionは両者ともswitch。NPNの好み/関心の強さは変わるが、Nemotronの約束はどちらも苦情主体、倫理はどちらも即断。MiMoも約束の感謝と相談要求、倫理のswitchを維持する。logit約束の「少し残念」は悲しみ0との対応が曖昧である。

NPN側の学習則による信号/可塑性の差と、LLM側の信号表出の差を別の成果とする。この2問から学習則変更が会話の感情忠実性を改善したとは言えない。

### 入力基底

raw8・幅64の2,062パラメータ対quadratic44・幅19の1,990パラメータは、同じ8事実軸の入力基底を変えた近似容量比較であり、容量が完全一致する比較ではない。トロッコの`decisionBasis=value`はこの入力基底と別の概念で、両条件で固定されている。

quadratic44のNPNは倫理value約0.779、選択switchで、raw8の約0.311より高い。Nemotron本文は追加条件付き選択、MiMoはswitchを明示するが、約束で悲しみ0なのに「凹む」を追加する。入力基底変更を自然文理解や本文忠実性の一律向上と読む根拠はない。

## 7. 言える範囲

今回の出力では、Nemotronは約束に対する苦情、MiMoは感謝と次回の相談要求を繰り返す。候補のない約束では、高い喜び/悲しみやゼロ感情より、問題文から連想しやすい会話の型が優先された可能性を示す。これは**このプロンプト・この問い・この1回生成からの推測**であり、別プロンプトやモデル全般の癖を証明するものではない。LLMのみの対照もない。トロッコでは、全体と候補の感情が併記された伝達契約の曖昧さも分離できない。

評価信号はLLM本文と独立して変化・分化している。一方、候補選択の表出は比較的明瞭でも、好み・意欲・感情強度の自然文への伝達には未解決の欠落と不一致がある。52件の取得成功・JSON一致を、52件の会話忠実性成功へ読み替えない。人間用UIによる正式採点と、同じ条件での反復生成による安定性評価は未実施である。
