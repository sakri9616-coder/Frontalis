# 100万近似診断の計算装置変更：結果選別と区別する

2026-10-15。CPU float64で100万モデルの通常形成8条件が完了。100万の凍結教師診断では1セル（5学習率×128epoch×192例）が並行CPUで約6分かかった。一方、別性能測定で100万のGPU float64更新はCPUより短かった。**計算時間を理由に**追加近似診断へGPUを使う。最終100万テストの結果を見て良い条件だけ残す変更ではない。

原 `01b-million-protocol.md`、主CPU228形成・24長期・336診断、100万CPU形成8・長期2、完成済みCPU100万診断cacheを保全する。進行中CPU診断は成功セルの保存後に終了し、未完のCPU24セルを完了したと報告しない。CPU100万の完成部分は装置差の校正資料として残す。

追加GPU診断を次の条件で、結果取得前に固定する。

- **10万と100万の両方をGPU float64で全24セル**。同一装置の二つを比べ、CPU10万対GPU100万だけの差を容量の効果にしない。
- 3物理条件×4教師出自×plain/composed、訓練192・検証64・最終256、同じ5学習率と128epoch。教師・訓練・検証ラベルを旧CPU実行器でJSON固定し、同じbytesをGPUへ渡す。
- 元のモデル式、16/h規格化、初期seed、自己評価関数・入力・損失を変えない。GPUを使う環境は性能試験済みの新ラボ専用Torch 2.7.0+cu128。
- まず既完CPU100万セルとGPUの同じセルを校正し、各候補の検証MSE・選択学習率・出力差を記録する。10万の全GPU結果と既存CPU結果の差も監査する。
- 検証で選択を固定してから48セルの最終評価へ進む。最終結果を見てhyperparameterや教師を変更しない。
- 装置による差が大きければCPUとGPUを混合せず、GPU同士の比較を独立した追加条件として報告する。小さくても完全なbit一致を仮定しない。
- GPU診断・状態・装置校正は別ファイルへ保存する。CPUの通常人格状態だけを既定の追加日本語会話に用いる。20件の重点比較と主52発言は変更しない。

この変更は計算運用上の技術的修正で、初期事前計画そのままのCPU100万全診断ではない。最終報告で変更理由、完成したCPUセル数、GPU比較条件、装置差を明示する。
