# Phase 3-D：容量拡張を判断する根拠

## 今回採用したもの

Phase 3-Cの自己評価循環を、更新対象の幅を変えられるPyTorch版へ移した。既存の526要素版は独立コピーからNumPy互換経路で再現する。容量比較では層数、事実8軸、出力7尺度、経験、自己増幅、更新率、更新回数、記憶再生上限を維持する。大きいNNを作ることと、複雑な人格を獲得することを区別する。

隠れ幅の変更は初期出力だけでなく更新幅も変える。幅が大きくなるほど同じhyperparameterが同じ関数更新になるとは限らないという問題は、YangらのTensor Programs Vでも扱われている。本試作はそのμPパラメータ化を採用したものではなく、単純な16/hの読み出し規格化で比較系列を定義した。幅による最適化・表現の変化は依然含まれるため、無規格化との補助確認や検証データでの学習率選択も分ける。[Tensor Programs V](https://arxiv.org/abs/2203.03466)

入力基底を二次積へ広げた条件を容量と別軸にした。これは事実が増える意味表現ではない。現在の8軸の注釈だけで、責任、同意、複数人の利害、時間的文脈を十分に表現できるとは考えない。自然文から豊かな潜在状態を学ぶ方法は検討対象だが、今回は容量の原因を切り分けるため新しい文章encoderや大規模モデルを導入していない。

## 強い比較対象

通常の人格循環では各モデルが自分で作るラベルが異なる。そこで、自分の目標への誤差の小ささを方式の優劣に使わない。未知入力における形成・分化・分化の保持・可塑性・数値健全性を別々に記録する。

近似能力は、既に形成された外部評価関数を凍結した別診断で比べる。NN、線形、二次、検索に由来する教師を均等に使い、各方式に同じ訓練・検証・最終入力を渡す。線形と二次は閉形式ridge回帰、検索は帯域検証を用いる。基本線形だけに勝ってもNN固有の必要性とはしない。数学的合成課題の成功も、その合成則が普通の経験から自律的に生まれた証拠とはしない。

## GPUと再現性

今回GPUの使用が許可されたため、旧CPU環境を変更せず、新ラボ内にCUDA版PyTorch環境を作成した。実際のCUDA演算を行って検証する。公式のWindows/CUDA導入経路を利用するが、主数値条件は従来のCPU float64環境のまま固定した。[PyTorch公式導入](https://pytorch.org/get-started/locally/)

GPU処理は非同期なので時間を測る前後に同期する。PyTorchが管理するallocatedとreservedは、他アプリを含む端末全体のVRAM使用量とは異なる。ピーク統計をリセットして実測し、CPU推論・プロセスRSS・純粋な重みbytesも別に報告する。[CUDAの公式説明](https://docs.pytorch.org/docs/stable/notes/cuda)、[メモリ統計](https://docs.pytorch.org/docs/stable/torch_cuda_memory)

## 今回採用しないもの

- 言語モデル本体の重み学習、Claude CLI呼出し、有料API。
- NPNの増大に合わせた層数・入力意味・学習則の同時変更。改善の原因が曖昧になるため。
- 新しい接続基盤やネイティブMCPの再開発。既存の無料OpenCode呼出しとホスト評価ツールを再利用する。
- NPN出力を人格プロフィールへ言い換えてからLLMへ渡す方法。返却信号の忠実さを直接測る。
- 開発者が好悪・倫理の正解を置く教師。経験の観測結果から、更新前のNPNが作る評価を学習する。
- 先に100万要素を作り、良かった結果だけを選ぶこと。事前の検証ゲートを満たした場合のみ追加する。

Generative Agents、外部記憶、継続学習、ブラックボックスLLMとの責務分離の調査は保全したPhase 1〜3-C資料を引き継ぐ。今回の新規根拠は容量・最適化・測定の切り分けに限定する。意識や主観的感情の実在は評価対象ではない。
