# Phase 3-Dの重点20ペア評価

この画面は、人が経験・条件・NPNの信号・実際の日本語発言を対応させて見るための資料である。内部予測の数値試験、LLMの返答に付いた自己申告ラベル、正式な人間採点は別の証拠として扱う。UI試験用の採点は人格の評価結果ではない。

## 比較の固定

`reports/review-selection.json` は回答取得前に固定し、10組×匿名の会話エンジン2種＝20ペアを指定する。良い回答や容量拡張が成功した組を見て選ぶ処理はない。

| 組 | 見る違い | 履歴の扱い |
|---|---|---|
| 01–02 | 同じ初期状態から、異なる2系列の経験による形成 | 経験前と96件の経験後 |
| 03–05 | 約束変更の場面で、モデル容量による違い | 同じ96件 |
| 06–08 | 未知の葛藤の場面で、モデル容量による違い | 同じ96件 |
| 09 | 同じ容量・初期評価・経験に対する学習則の違い | 同じ96件 |
| 10 | 8事実軸の数学的な入力表現の違い | 同じ96件、容量は近似的に一致 |

生成方式・モデルの実名・パラメータ数・どちらのモデルが大きいかは表示に含めない。比較条件の種類、事実履歴、NPNの信号は示す。したがって、すべての情報を伏せた自然会話の好感度試験ではない。信号を先に見たことによる採点への影響は画面にも明記する。

## 採点

3項目を別々に1～5で採点し、判断できなければ未採点のまま残せる。

- **内的信号への忠実さ**：好き嫌い・意欲・反抗・感情・候補判断の方向と強度が、提示されたNPNの信号に対応しているか。
- **会話の自然さ**：通常の日本語会話として、場面に応じた返答になっているか。
- **経験・条件と発言の対応の納得感**：履歴または比較条件と、変わった点・保たれた点の関係を理解できるか。

容量の大きさ、反応の極端さ、倫理的な賛否、穏やかさを高得点の条件にしない。強い好き嫌い・反抗・頑固さはそれだけで欠陥ではない。理由を毎回説明することも必須ではない。経験の追加がない容量・学習則・入力表現の組を、経験前後の変化とは扱わない。

意欲・嫌悪・反抗は選好からの固定読出しである。独立して意欲・反抗を学習した証拠とはしない。トロッコの設問は変更と人数損失の葛藤への転移であり、責任・同意や倫理一般の判断能力を実証するものではない。

## 履歴と信号の表示

経験の集計には元データだけを使う。領域別の件数と、完成・損失・発見の観測値が3分の2以上だった件数を表示し、対応する経験IDを追跡できる。これを本人の好み・感情の要約や学習の正解とは呼ばない。LLMの回答内容・NPNの値から代表例を選ばない。

代表例は先頭・中央・末尾の最大3件である。出来事と結果を分け、全履歴の原文は折りたたんで保持する。各原文には、入力・結果の8事実軸を含む元の経験記録をそのまま確認できる欄がある。粗い自然文だけで8軸の違いがすべて分かるとは主張しない。

同一履歴は比較A・Bと2つの会話エンジンで共有し、一度だけ表示する。履歴差はIDと原文だけから機械的に取り出す。NPN信号は方向と中立な強度帯で示す。0は「なし」、0より大きく1/3未満は「弱」、1/3以上2/3未満は「中」、2/3以上は「強」であり、高得点の基準ではない。丸め前の精密数値は折りたたみ欄にすべて保持する。関心の正負の評価と、正の値だけを取り出した好奇心の表出強度は別々に示す。理由寄与を計算していない場合、表示側で理由を生成しない。

意欲・反抗・感情の方向は常時見える。重複する単一対象の選好表と感情の詳細表は補助欄に折りたたみ、候補を持つ価値判断は常時表示する。候補の順位は評価値の高い順で、同じ値は同順位とする。NPNが差の小ささから保留した判断も保持し、表示側で選択を確定しない。

## 実発言の照合

`scripts/build_review.py` はLLMを呼ばず、固定された選択と取得済みキャッシュから画面データを構築する。

1. スナップショットのメタデータSHA、パラメータアーカイブSHA、世代、パラメータハッシュ、履歴を固定されたツール出力と照合する。容量・入力表現・学習則・モデル種別も固定された条件と照合する。
2. キャッシュのエンジン・組ID・プロンプトSHAとCLI成功を確認し、想定外のCLIツール呼び出しを拒否する。
3. 採用する返答JSONがモデルの原出力と一致することを確認する。本文を補筆・編集しない。
4. 取得時のプロンプトに含まれた場面とNPN信号を固定計画と照合する。
5. ローカルツールの要求、スナップショット、返却信号の実行跡も照合する。
6. 欠落・改変があれば停止する。仮の返答や架空の発言で埋めない。既存の表示データが違う場合も上書きしない。

取得前の計画が `reports/live-plan-pre-materialization.json` と `reports/pre-replies-sha256.json` に保存されている場合は、そのSHAを検証し、計算済みのツール出力を追加する以外に計画が変わっていないことも照合する。

取得元・方式・モデル実名・ハッシュは別の `reports/review-key.json` に保存する。この対応表は採点用HTMLに含めない。再利用した実発言の固有件数と、比較で表示する延べ件数を分ける。

## 保存と再開

採点と任意メモをブラウザー内へ自動保存し、JSONでも保存・読込みできる。外部送信はない。Phase 3-D専用の `selectionId` と表示データのSHAで照合し、旧研究や違う会話データの採点が混ざることを防ぐ。旧研究の評価画面・保存ファイルは変更しない。

## 再現と検証範囲

新ラボで次を実行する。

```powershell
python -m unittest discover -s tests -p test_review.py -v
node scripts/test_review.cjs
python scripts/build_review.py
node scripts/review.mjs
```

Pythonの21試験はキャッシュ・固定計画・元の発言・信号・履歴・スナップショットの改変を検出する。Nodeの32試験は表示契約、原文・8軸の保持、匿名条件、強い反応の保持、共有履歴、採点保存・再開、異なるデータの拒否、スクリプト安全性、強度帯の境界・同順位・精密数値の保持を確認する。試験用の架空のUIデータは `runtime/review-ui-tests` に置き、研究発言へ流用しない。

これらは構造と処理の試験であり、実ブラウザーの操作確認は別途記録する。正式な人間採点は、実際に人が評価を入力するまで未実施である。

## 今回生成した実データ

2つの無料会話エンジンから取得した52件の実発言キャッシュを照合し、回答取得前に選んだ10組・20ペアを `reports/review.html` に生成した。画面に表示する発言は延べ40件、再利用を除いた固有の実発言は24件である。代表例は96件の履歴の1・48・96件目で固定され、全経験の原記録と8事実軸注釈を保持する。比較01・02は経験前0件／経験後96件、比較03〜10は同じ96件を使う。

生成したHTMLにはモデル実名、状態保存先、パラメータハッシュ、容量の実数を入れない。取得元との対応は `reports/review-key.json` に分離した。実キャッシュからの構築と、上記53試験は合格した。採点ファイルの表示データ識別子は `a012747260a1ea6e35f31aff7447ba91be9978c7e1f6ba741513f5daefc4b74a` である。強度帯による簡潔表示への変更前後でも同じ識別子を維持し、保存済み採点JSONとの互換性を保つ。

これは画面と取得データの照合結果である。会話の良さを正式に人間が採点した件数は、生成時点では0件である。実ブラウザーでの表示・保存再開の操作確認は、研究本体の検証記録を参照する。
