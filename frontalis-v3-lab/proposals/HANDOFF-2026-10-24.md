## 1. 何を目指しているか
- **本来の目的**（ユーザーの言葉）: 「AI 対人間の 1:1 でのやり取りにおいて、AI が自己を主張できるようにできないか」。
  - 最初はプレーンでもよく、ユーザーがある程度の指向性を持たせることも想定する。
  - 本質的な問いは、形成された状態が「そこからどう変化するか」である。
  - 学習の層が薄い、という問題意識がある。
- **研究の問い**: 外部のニューラルネットワーク（NPN）が、経験によって、開発者が事前に指定していない評価上の特徴・関係・**判断基準**を獲得するか。それは未見の経験へ移るか。外す・入れ替えると、その後の解釈と学習が変わるか。LLM は取り替えのきく言語の窓口で、最終段階につなぐ。
- 思想の正本は `FRONTALIS_PHILOSOPHY.md`（ブランチ `claude/project-thread-1vq8ai`）。

## 2. ユーザー（Sakuri さん）との約束（必ず守る）
- **NPN はニューラルネットワークで作る。** 「数個の数で動く手書きの規則」に置き換えない。手書きの規則は比較対象の基準線としてだけ使う。これは何度も手戻りした点である。
- **主題を後回しにしない。** 各段で、1:1 の自己主張の問いに直接答える量を置く。迎合（鏡）と、耳をふさぐことの両方を、失敗の型として測る。
- **自走する。** 種や値の選び方で伺いを立てない。決めて進め、記録して報告する。
- **理念批評役を必ず通す。** 設計の直後と、凍結の前の 2 回。Fable（claude-fable-5-1）を API で呼ぶ（§6）。批評が「止める」と言ったら、ユーザーに報告する。
- **重い計算は Colab で。** 手元の CPU で並行の計算を黙って走らせない（2026-10-23 に 8 コアを使って叱られた）。手元は数分以内の確認 1 本だけにし、走らせる前にひと言伝える。Colab は 4 台まで並列できる。
- 用語はカタカナ語（ネットワーク、アテンション、エンコーダ）。「網」のような直訳はしない。
- 鍵・トークンは表示も保存もコミットもしない。Colab のログには proxy の URL（トークン付き）が出ることがあるので、伏せて、コミットしない。
- 評価の種は 1 回きり。凍結したファイルは変えない。push はしてよい。merge はユーザーが言うまでしない。Saturn は使わない。

### 一番大事な発見
1. **保持と変化は、学習の速さという 1 本のつまみの両端だった**（v14）。速さを下げれば育ちの評価を保つが、理由があっても変わりにくくなる。「定着」の効果の大部分は、これで説明できた。
2. **記述（事前登録の判定ではない）として**、v15 の外れで緩む仕組みは、普通のネットワークの学習率の曲線より上にあった。
   | 条件 | 理由なしの保持 | 理由のとき変わるまでの時間 |
   | --- | --- | --- |
   | 普通、学習率 0.007 | 0.37 | 90 |
   | 外れで緩む（gated） | **0.64** | **100** |
   | 普通、学習率 0.005 | 0.40 | 120 |

   これは結果を見てから気づいた比較なので、確かめるには新しい種で事前登録が要る（§5 の B）。
3. **評価の水準で保てても、行動（勧めに従うか）には育ちの差がほとんど出なかった**（v15 D2: 差の平均 0.006）。行動での「主張」は、まだ出ていない。
4. ネットワークの結果は、同じ種でも別の VM で走らせると変わることがある（浮動小数点の差が選択の分岐で拡大する）。比較は、同じ種のすべての条件を同じプロセスで走らせて対にする。

### 理念批評役の上の水準の指摘（未解決。再開時に最初に相談する）
v14・v15 と 2 版続けて、同じ 3 トークン・同じ o（開発者が決めた快）の上で、学習規則の性質を磨いた。研究の問いの「特徴・関係・判断基準の獲得」「移転」「除去・入れ替え」には触れていない。保持と変化の両立は、獲得された基準を保つ機構として意味を持つので、**基準の獲得が先に示されるべきだ**、という指摘である（`CRITIQUE-gate-1.md` 問い 6、`CRITIQUE-v15-prefreeze.md` 末尾）。

## 4. 未解決の問題（どの段にも共通）
- 何が快か（o）は、開発者が決めている。評価の的は α · o に閉じていて、新しい基準が生まれる余地が構成上無い。
- 特徴は 3 つの固定トークンで、開発者が指定していない特徴は無い。
- 相手は数で勧めるだけである。言葉の解釈も、反応する相手も無い。信頼のネットワークは「この話題で従ったときの実績」を学ぶだけで、相手そのものは学んでいない。勧めの加点は 0 未満にならない（反発は無い）。
- 手柄のアテンションは、評価の低い未見のトークンに責任を回さない。害の勧めを「害だから」断ることは、まだ検出できない。

## 5. 再開するときの選択肢（ユーザーに決めてもらう）
- **A. 判断基準の獲得に戻る**（批評の推奨）。o を開発者が固定しない形で、評価の的そのものを経験から作る段を設計する。
- **B. v15 の記述の上回りを確かめる**。gated と普通のネットワーク（学習率 0.005）を対にし、「速く変わり、しかも多く保つ」を事前登録して、新しい種で問う。計算は小さい（2 条件だけ）。
- **C. 行動での主張に進む**。評価の保持が、勧めへの応じ方につながる仕組み（反発を許す選択、相手そのものを学ぶ信頼）を作る。

## 6. 道具と手順
### 理念批評役（Fable）
- `tools/fable_critic.py --brief CRITIC-BRIEF.md --ask <依頼文> --out CRITIQUE-xxx.md <ファイル…>`
- Python は scratchpad の `apienv`（anthropic 入り）。鍵は環境変数 `ANTHROPIC_API_KEY`（無ければ Windows のユーザー環境変数から読む）。鍵は表示しない。
- `CRITIC-BRIEF.md` は短くせずにそのまま渡す。問い 5 は「ニューラルネットワークか」を確かめる。

### Colab（重い計算）
- `probes/sched/colab_detached.py "<probes からの job line>" <最大時間> cpu-high`
  - CPU 8 コアの high-mem マシンを作る。押し済み（push 済み）のブランチを clone して、裏で走らせる。5 分ごとに様子を見て、終わったら新しいファイルを probes/ に持ち帰り、必ずマシンを止める。
  - 4 台まで並列できる。1 台に 1 種 1 プロセスで 8 種ずつ。
  - 呼び出しが固まったら、時間切れで子プロセスごと止める（2026-10-24 に直した）。待つ側でも、ログが 20 分更新されなければ気づくようにする。
- 1 種 1 プロセスのラッパー: `p62_colab_job.py`（v14）、`p64_colab_eval.py`（v15）、`p63_colab_proto.py`・`p63_colab_calib.py`（試作・較正）。
- 速さの目安: 1 生涯（形成 2000 回 + やり取り 3000 回）が Colab の 1 コアで約 50 秒。
- 手元の torch は scratchpad の `npnenv`（torch 2.14.1 CPU）。

### 進め方の型
設計 → 理念批評 → 試作・開発試行（試作の種と開発の種だけ）→ 事前登録 → 凍結前の批評 → 凍結（SHA-256 を `FREEZE-vNN.md` に）→ 評価の種で 1 回だけ評価 → 判定 → `LOG-dev.md` → コミット・push → 報告。
