## メモリについての訂正（2026-10-17）

本番規模の区画が 11.0 GiB の配列を確保できずに失敗した件は、**ホストの RAM**（このマシンは 32 GB、他の処理と共有）の問題である。`sim4.py` の `_stack`（`np.stack`）が、形 (720, 128000, 32) の float32 の乱数の列を一度に作ろうとした。以前はリーダーの文面も含めて「GPU のメモリ不足」と書いていたが、誤りである。対処は、乱数の列と経験の生成を 1,000 経験ごとに分けること（chunked RNG）。これとは別に、**GPU の VRAM**（RTX 3050、8 GB、他のエージェントと共有）では、複数の試行を同時に走らせたときに CUDA out of memory が起きた。こちらの対処は、1 本ずつの待ち行列と VRAM の削減である。両者の区別は `DESIGN.md` 第 10.1 節と `probes/LOG-dev.md` に書いた。
