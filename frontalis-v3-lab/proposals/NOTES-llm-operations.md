# 設計メモ: LLM 運用の軽量化（プロンプトキャッシュ）

記録日: 2026-10-17。記録者: リーダー。発案: Sakuri さん。**覚書であり、事前登録の一部ではない。未検証。**

## 覚書の内容

LLM に NPN の状態を渡す検査（DESIGN 第 9 節、PREREG 第 11 節）で、コンテキスト（LLM に一度に読ませる文章）が肥大化するのを防ぐために、プロンプトキャッシュを使う運用を検討する。

## 見立て（検証前）

- 検査のプロンプトは、**固定の部分**（固定のシステム文、場面の説明、出力の形式の指示）と、**変わる部分**（NPN の状態の文章、A ↔ B の入れ替え）に分かれる。固定の部分を先頭に置き、変わる部分を末尾に置けば、固定の部分がキャッシュに乗る。
- 主の因果の対照は「同じプロンプトの中で、NPN の状態だけを入れ替える」ものなので、もともと末尾だけが変わる形をしている。キャッシュと相性がよい。
- 豊かさの階段（L-0〜L-3）は、段が上がるほど、変わる部分が長くなる。固定の部分を共通にしておけば、段を上げて再検査するときも、固定の部分を再利用できる。

## 気をつけること

1. **キャッシュが減らすのは、費用と待ち時間であって、コンテキストの長さではない。** LLM は、キャッシュに乗った部分も含めて全部を読む。長さそのものを減らすには、L-2 のように、根拠を構造化して要約する工夫が別に要る。
2. **キャッシュが効くのは、先頭から同一の部分だけ。** 先頭に日時や呼び出し番号などの変わる文字を入れると、効かなくなる。固定の部分は、文字単位で同一に保つ。
3. **提供元ごとに仕組みが違う。** この環境で使える経路（Claude Code のセッション内のエージェント、OpenCode 経由の無料モデル）で、キャッシュが効くかは、**まだ確認していない。** Anthropic の API は残高不足で使えない。使う前に、経路ごとに、実際に効いているか（応答の時間、利用量の表示）を測る。
4. **実験の統制を弱めない。** キャッシュの有無で LLM の出力が変わらないことを、開発用の小さな検査で確かめてから使う。固定の部分を共通にすることは、むしろ条件をそろえる助けになる。
5. プロンプトと出力の全文を保存する決まり（PREREG 第 11 節）は、そのまま守る。

## 次にやること（LLM の検査を具体化するとき）

- 経路ごとに、キャッシュが効くかを 1 回ずつ測る（固定の部分を同一にして 2 回呼び、2 回目の時間と利用量を比べる）。
- 固定の部分と変わる部分の境目を、プロンプトの雛形に書く。
- 効く経路だけで採用する。効かない経路では、通常どおりに呼ぶ。
