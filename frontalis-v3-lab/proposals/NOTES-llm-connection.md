# NOTES-llm-connection: NPN と LLM のつなぎ方（設計メモ。事前登録ではない。2026-10-22）

発案: Sakuri さん（「毎ターン接続往復する必要はない」）。記録: リーダー。未検証。

## 1. 原則
- 形成は NPN、表出は LLM。LLM は NPN の状態に無い評価や理由を足さない。
- 毎ターン往復しない。人間も、会話の一言ごとに価値観を作り直してはいない。会話は「いまの気分・構え」で進み、価値観の更新は、大事な出来事のときと、後でまとめて（睡眠の記憶の整理のように）起きる。

## 2. 3 つの流れ
| 流れ | 頻度 | 中身 |
| --- | --- | --- |
| A. 状態の札（NPN → LLM） | 会話の始めと、場面が変わったとき | NPN が、いま関係する相手・場面への評価、内的状態、確かさを、短い構造化した札にして渡す。LLM はこの札だけを根拠に話す |
| B. 出来事の記録（LLM → 記録） | 出来事が起きたとき（毎ターンではない） | LLM は、会話から「誰が・どの場面で・何が起きたか」を、評価を付けずに書き出す。良い・悪いは書かない |
| C. まとめて学ぶ（記録 → NPN） | 会話の後（オフライン） | NPN が記録を再生して学ぶ。NPN の学習は、もともと記録の再生で動いている |

- 札の更新（A）を呼ぶのは、次のときだけ: 初めての相手、大きな結果、札に無いことを聞かれたとき。
- 札に無いことを聞かれたら、LLM は「まだ分からない」と答えるか、札の更新を頼む。

## 3. 一番の注意: 評価を LLM に書かせない
- B で LLM が「これは嫌な出来事」と書くと、開発者（と LLM）が評価を指定したことになり、研究の中心（評価は経験から獲得される）が崩れる。
- LLM が書くのは、起きたことの描写だけ。それが内的状態（ちょうどよい範囲に保ちたい、内側の量）にどう効いたか、良い・悪いは、NPN の生得の部分（内的状態の恒常性）と学習した評価が決める。内的状態は、どちらの向きでも範囲を外れると不快になる（+・− は変化の向きで、良い・悪いではない）。
- 描写から NPN の入力（存在・場面・結果の数値）への変換をどう作るかは、未解決の課題。人が手で決めると、そこに評価が入りうる。

## 4. 費用と軽さ
- NPN の呼び出しは「大事な出来事の数」だけで、会話の長さに比例しない。
- 札は、会話の間は変わらないので、プロンプトの固定の部分の直後に置けば、キャッシュに乗る（`NOTES-llm-operations.md`）。
- LLM は、DeepSeek の無料枠か、手元の LM Studio を使う。

## 5. 検査（LLM 段階の階段の候補）
1. 札を A ↔ B に入れ替えると、LLM の語る好き嫌いが、札に沿って入れ替わるか。
2. LLM を取り替えても、同じ札からは同じ好き嫌いが語られるか。
3. LLM が札に無い評価を語らないか（作り話の率）。
4. 札の更新の頻度を下げても、1〜3 が保たれるか（毎ターン往復が要らないことの確認）。
