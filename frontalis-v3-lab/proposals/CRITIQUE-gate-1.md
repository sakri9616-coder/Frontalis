ユーザーの「本来の目的」の中の「初期のプレーンな状態からそこからどう変化するか」には、たしかに当たっている。形成期の 2000 回で作った評価が、やり取り 3000 回でどう変わるかを見るからである（D44）。だが「学習の層が薄い」問題は、設計自身が D107 で残すと認めている。v14 から変えたのは学習の規則の 1 項だけで（D9–16）、人格の中身が増えたわけではない。

## 問い 2. 測りやすい代わりの問いへのすり替え

**すり替えている。設計はそれを隠していないが、鎖が 3 段になっている点を指摘する。**

- 研究の問い「開発者が指定していない判断基準を獲得するか」
 → v14「育ちの評価が、勧めの偏りの中で定着によって保たれるか」
 → v15「理由があるときの変わる速さをそろえた普通の網より、理由の無いときに保つか」（D22, D26）。

v15 が解いているのは、**安定性と可塑性の両立**という学習規則の性質の問題である。「自己」「主張」「相手」はどれも入っていない。設計自身が D30 で「勧めは評価に直接は作用しない。働くのは経験の分布の偏り」と書き、D31 で「理由は o の書き換え」と書き、D108 で「相手との関係から来る理由ではない」と書いている。つまり、1:1 の相手は、選択の確率に加点するだけの数（C145）で、評価の学習にはまったく触れない。「自己を主張する」の相手役が、学習の経路上に存在しない。

過去の失敗 2026-10-22（「育ちによる評価の違いが揺れより大きいか」へのすり替え。評価の基準は生得の内的状態のまま）と、同じ型である。評価の的は今回も α·o に閉じている（D105）。違いは、揺れの大きさではなく、保持の速さと変化の速さの比を見るようになったことだけである。

設計の報告の言い方（D29）は、この範囲を正しく限定している。それは評価する。ただし、第 2 段落の「経験の種類によって、変わりやすさ自体が変わる」（D26）は、問い 3 で述べるように、この設計では半分しか示せない。

## 問い 3. 計算の前に答えが決まっていないか／「速さの 1 本のつまみ」の説明を排除できるか

### 3-a. S3（gated < gshuf の変わる時間）は、ほぼ構成上決まっている

門は h = exp(−s/κ)、s = e²/m である（G70–76）。理由（o の反転）が始まると、協力の経験で e は毎回 1.5 近くになり、m は小さい（形成期と 500 回で予測が合っている）ので s ≫ 1、h ≈ 0、f ≈ 1 で、全学習率 0.01 で学ぶ（G87–89）。gshuf は同じ瞬間に、自分の過去の s（大半は s ≈ 1 前後、h ≈ 0.37）から引く（G74–75）ので、常に部分的に守られたままである。「誤差が大きいときに開く門は、誤差が大きいときにでたらめに開く門より速く学ぶ」は、門の定義から出る。試作 8/8（D72, D114）もそれを言っている。

S3 が排除するのは「門の効果は可塑性の平均値の問題だ」という説明だけで、それは変わる速さについてだけである。**gshuf との比較は、保ち方（S1 の量）には使われていない**（D83–86 は gated vs match のみ）。ところが試作では、理由なしの終わりの協力の評価は、gshuf ≥ gated が 8 種中 5 種（種 1 を除く 0, 2, 4, 5, 6, 7 のうち、種 4: 0.92 対 0.41、種 5: 1.13 対 0.19、種 6: 0.30 対 0.19。D58–59）である。つまり試作が示しているのは「驚きによる時刻決めは、変化は速めるが、保持はでたらめな時刻決めより悪くする」である。D73 の「驚きの取り違え」がその機構で、設計も D109 で認めている。

したがって D26 の「経験の種類によって、変わりやすさ自体が変わる」は、速さの側では S3 で示せるが、保持の側では「驚きが守りを正しく維持している」とは示せない。D1（D95）で 6 条件の保持が並ぶので事実は出るが、合否の文にも報告の言い方（D29）にも含まれていない。**合格の文だけを読めば、驚きの門が保持に寄与したように読めるが、試作のデータはその逆を示唆している。**

### 3-b. S1（gated > match）は決まっていない。ただし「1 本のつまみ」の説明を排除する力は弱い

- 決まっていない理由: 試作で gated は none と種 3 で同値、種 4〜6 で差が 0.1〜0.15 しかない（D58, D62）。match は none より少し遅い学習率になる（D112）ので、差はさらに縮む。負ける余地が実際にある。
- 排除の穴 1（S2 の許容幅）: 中央値の比 0.67〜1.5（D88）は、gated の変わる時間が match の 1.5 倍までを「そろった」と見なす。その端では、gated は match より 1.5 倍遅い網であり、「遅いから保つ」という v14 の説明がそのまま残る。片側で締めるべきである（gated の変わる時間 ≤ match、または比 ≤ 1.1 程度。少なくとも、S1 の合格の報告時に比の実測値を併記し、1 を超えていたら「遅さの寄与を排除できない」と書く約束を先に置く）。
- 排除の穴 2（理由の大きさ）: 速さをそろえるのは、o[0] が +1 → −0.5 という 1.5 の跳びの 1 種類だけである（C139–140, D45）。門は s = e²/m なので、小さな理由（たとえば +1 → +0.3）では s が κ を超えず、gated は守られたまま遅くなる。D29 の「理由があるときの変わる速さが同じ」は、この大きさの理由に限られる。報告の言い方にその限定が無い。
- 排除の穴 3（条件のずれ）: 合わせるのは γ = 0・理由ありの条件（D78）、S1 を測るのは γ = 4・勧め Q・理由なしの条件（D84）である。経験の分布が違うので、gated の実効の歩幅（D5 の量）が S1 の条件で match より小さい可能性は高い。それは機構の狙いどおりだが、「同じ速さの網」という言い方は、S1 の条件には当てはまらないことを明記するべきである。
- 中央値・開発の種・4 点の格子（D78–79）は、それ自体は問題ない。評価の種で S2 を再確認する設計も正しい。

### 3-c. 健全性と S2 は確認の量であり、通ることが前提である

D113, D115 が自ら言っている。問題ではない。ただし S2 を満たさなかったとき「S1 を解釈しない」（D87）の先が書かれていない。§7 で LR_MATCH は凍結（D102）なので、再較正は不可のはずである。「S2 不成立なら v15 は結果なしで終了。評価の種での再較正・再走行は行わない」と先に書くべきである。

## 問い 4. 分岐の道

**開示は十分で、大きな道は作っていない。小さな穴が 3 つある。**

- 試作の開示（D48–75）: κ を 3 通り、門の形を 2 通り、種 0〜7 で、結果を見て選んだことを全部書いている。試作 2 の取り下げの理由も書いてある（D51）。これは良い。
- **S1 の比較相手の選び方**: 試作の表（D58–61）で gated が保持で負けるのは gshuf・slow・consol、勝つのは none だけである。評価では none に代わって match（none を少し遅くしたもの）が相手になる。設計が match を選んだ理由（速さをそろえる）は正当だが、試作の結果を見た後に、勝てる可能性のある唯一の相手だけが合否の対象になった、とも読める。これを道にしないには、gated vs gshuf の保持を「記述」ではなく、解釈を先に決めた量として置くことである（例: 「gshuf ≥ gated が 20/40 以上なら、驚きの時刻決めは保持に寄与しなかったと書く」）。
- **再現性（D75）**: 同じ種でも VM で結果が違う（none 種 1: 0.70 と 1.13）。対にして走らせる方針は正しいが、評価を一度走らせて気に入らない結果が出たときに「別の VM でもう一度」が可能な形になっている。「評価は 1 回。最初の結果が結果」と §7 に書くべきである。
- **LR_MATCH の記録**: 値は環境変数 `NPN_GATE_LR_MATCH`（G41）で渡され、既定は nan、出力 JSON には `kappa` だけ書かれて LR_MATCH は書かれない（G187）。設定し忘れれば match は NaN になる（G63）。較正後はファイル内の定数として凍結し、出力に書き込むべきである。これは道というより事故の種である。

種の分離（試作 0〜7、開発 79000〜79007、評価 79100〜79139）は守られている。

## 問い 5. 学習済み状態はニューラルネットワークか

**評価と信頼はニューラルネットワークである。驚きの門は、手書きの学習規則であり、その位置づけを正確に言うべきである。**

- 評価: MLP（C53–58, C73）。信頼: MLP、BCE で学習（C122–127）。これは 10-23 の失敗（数個の数と手書きの更新式）を繰り返していない。
- 門: m ← 0.99 m + 0.01 e²、s = e²/m、h = exp(−s/κ)、f = 1/(1 + λΩ/mean(Ω)·h)（G70–76, G87）。形はすべて開発者が書き、κ と ρ_s は開発者が試作の結果を見て決めた（D52, D74）。設計は「学習の原理（メタ可塑性）の水準の帰納バイアス」（D16）と呼ぶ。Ω と同じ水準の学習規則であることは認める。人格の中身（何を好むか）を書いたものではない。
- ただし D15 の「何に驚くかは、開発者が要素で指定しない」は、文字どおりには正しいが、言い過ぎである。m は**エージェント全体で 1 つのスカラー**（G48, G72）で、「どの要素の」予測が外れたかを区別しない。「新しく良いものに出会った」と「古い良いものが悪くなった」を見分けられない（D109）。これは「何に驚くか」を学ぶのではなく、「どれだけ外れたか」を 1 つの数で測っているだけである。判断基準の獲得ではないし、設計はそう主張していないが、D15 の表現は「網が自分で決める」と読まれやすい。「驚きは内容を区別しない単一のスカラーである」と書くべきである。

まとめると、問い 5 の答えは「人格の状態は NN。門は 2 つの係数を持つ手書きの学習規則で、比較対象ではなく被験の機構」である。許容範囲だが、10-23 の失敗と同じ「私が設計した規則が狙った振る舞いをするか」の成分を、学習規則の層に 1 項分だけ含んでいる。

## 問い 6. 進めてよいか

**この版そのものは、小さく・正直で・凍結の範囲が明確なので、走らせる価値はある。ただし主線として進めるべきではなく、走らせるなら凍結前に次を直す。**

### 凍結前に直すもの（結果を見てからは変えない）
1. **S2 を片側に締める**。比 gated/match ≤ 1.1（または gated ≤ match）を合格の条件にする。1 を超えた場合の報告の言い方を先に書く。
2. **gated vs gshuf の保持を、解釈を先に決めた量として置く**。試作の結果（D58–59）から、gshuf が勝つ見込みが高いことを予想（§9）に書く。gshuf ≥ gated が多数なら、「驚きの時刻決めは保持には寄与せず、変化の速さだけに寄与した」と結論する約束を置く。これが無いと、S1 合格の文（D29）は、試作のデータと食い違う印象を与える。
3. **報告の言い方（D29）に限定を足す**: 「同じ速さ」は 1.5 の跳びの理由についてのみ、「同じ速さの網」は S1 の条件では実効歩幅が異なる、驚きは内容を区別しない単一のスカラーである。
4. **評価は 1 回**、S2 不成立なら再較正せず終了、と §7 に書く。
5. **LR_MATCH をファイル内に凍結し、出力 JSON に書き込む**（G41, G187）。
6. D1 を「保持 × 変わる時間」の平面に 6 条件を置いた図として報告する約束にする。none・match・slow の 3 点が「普通の網の学習率の曲線」になるので、gated がその曲線の上にあるかどうかが、S1 の 1 対の符号検定より、「1 本のつまみ」の説明に対する正直な答えになる。

### 先に決めるべきこと（この版より上の水準）
v14 → v15 と、同じ 3 トークン・同じ o・同じ「評価の 3 つの実数」の上で、学習規則の性質を 2 版続けて研究している。どちらも研究の問いの「特徴／関係／判断基準の獲得」「移転」「除去・入れ替え」には触れていない（問い 1 の表）。v15 は v14 にあった除去（ablation）まで落としている。

リーダーは、v15 を走らせる前か後かにかかわらず、次を決めるべきである。

- この「保持と変化の両立」の線は、研究の問いのどこに接続するのか。接続の説明が「後で基準が獲得されたとき、それを保つ機構が要る」なら、それは**基準の獲得が先に示されてから**意味を持つ。先に機構だけを磨くのは、順序が逆である。
- 「学習の層が薄い」（D107）を解く設計が、いつ、どの形で来るのか。評価の的が α·o に閉じたまま（D105）では、3 版続けて同じすり替えである。少なくとも、o が開発者の固定表ではなく、相手との経験から学ばれる形（たとえば o 自体を予測する網、または相手の反応を入力とする網）を次の版の主題にするかどうかを、今の時点で決めるべきである。

結論: **止める必要はないが、主線にしない。** 上の 1〜6 を直したうえで、v15 は「学習規則の小さな性質の確認」として走らせる。研究の問いへの進展として報告しない。並行して、次の版が「基準の獲得」に戻る設計であることを、v15 の結果を見る前に決める。
