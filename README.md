# Project frontalis

**経験によって人格が育つ AI は作れるのか。** その問いを、実験で確かめる研究です。

会話用の AI（LLM）の外に、経験から「何を好み、何を避けるか」を学ぶ小さなニューラルネットワーク（NPN: Neural Personality Network）を置き、それが本当に個性を持つ主体になるかを調べます。AI コンパニオン「ネフィア」の人格の土台として使うことを想定しています。

English: [README.en.md](README.en.md)

> **状況（2026-10-18）**: 研究の途中です。**「人格が形成された」と言える結果は、まだ得られていません。** 得られた結果と、うまくいっていない点を、第 3〜5 節にそのまま書いています。

---

## 1. この研究が目指すもの

現在の対話 AI は、人格らしい文章を書けます。しかし、それは「人格を演じている」だけかもしれません。この研究が調べたいのは、**経験を積んだ結果として、その AI の評価（何を良い・悪いとみなすか）そのものが育ち、次の経験の受け止め方が変わっていく**ことです。

作りたい循環は次のとおりです。

1. 今の人格が、経験を評価する。
2. その評価と、実際に起きた結果によって、人格が更新される。
3. 更新された人格は、次の経験を、以前とは違う仕方で受け止める。
4. これが積み重なって、**設計者が一つずつ指定していない、その個体固有の価値判断**が形づくられる。

役割分担は次のとおりです。

| 部品 | 役割 |
| --- | --- |
| LLM（Claude など） | 言葉の理解と表現を担当する「通訳」。入れ替えられる |
| NPN | 経験によって育つ、評価の主体。人格の中身はここにある |
| 経験記録 | 何が起きたか、当時どう解釈したか、後から何が訂正されたかの履歴 |

### 研究の理念（要点）

正本は [`FRONTALIS_PHILOSOPHY.md`](https://github.com/sakri9616-coder/Frontalis/blob/4fecbad/FRONTALIS_PHILOSOPHY.md)（固定コミット `4fecbad`）です。この研究が守る原則を、短く挙げます。

- **形成と表現は別物です。** LLM が人格らしく語れても、それは NPN が人格を形成した証拠になりません。「同じ LLM、同じ文面で、NPN の状態だけを入れ替えたとき、判断が変わるか」で切り分けます。
- **個性は、故障ではありません。** 固執や、嫌悪の持続、反論への抵抗は、人格の一部でありえます。故障と数えるのは、数値の発散、学習の飽和のような、計算としての破綻だけです。
- **基準を、結果に合わせて動かしません。** 何をもって成功とするかを、実験の前に固定して記録します。通るように調整することを、禁じています。
- **評価の学習率や係数を変えただけでは、人格が形成された証拠になりません。**

## 2. 中心の問い（2026-10-17 に定め直しました）

初期の実装は、研究したい問いを、解きやすい別の問いに置き換えていました。価値の種類（5 つの欲求）を開発者が決め、その重みを数式で更新するだけでは、**設計者が考えなかった評価の観点が、経験から生まれること**は、構造上ありえません。

そこで、中心の問いを次のように定めました。

> 経験によって、開発者が事前に指定していない評価上の特徴・関係・判断基準を獲得し、それらが次の経験の解釈と学習を変える仕組みを研究する。

「獲得した」と言うためには、次の 3 つを確かめる必要があります。

1. 獲得した特徴が、**初めての状況でも通用する**（丸暗記ではない）。
2. 特徴を**取り除いたり入れ替えたりすると**、その後の解釈と学習が変わる。
3. 異なる経験をした個体の間で、評価が**実際に分かれる**。

## 3. 現在の進捗

### 3.1 一目でわかる状況

| 確かめたいこと | 状況 |
| --- | --- |
| 経験から学んだ「期待」（行動の結果の予想）が、初めての状況に通用する | **確認できた**（複数の評価で再現） |
| 経験の違いが、評価の違いとして現れる | **一部のみ**。学習の偶然の揺れに、ほとんど隠れている（課題 1） |
| 評価の状態が、本人の次の学習を変える | **測り方の上では確認できたが、仕組みの効果とは言い切れない**（課題 2） |
| 学習した評価が、個体ごとに違う人格になる | **まだ示せていない** |
| LLM を入れ替えても、同じ NPN の状態で主張の向きがそろう | 設計済み。未実施 |
| 人間による評価 | 未実施 |

### 3.2 実験の流れと結果

実験は、判定基準を先に固定し（**事前登録**）、評価用の乱数は **1 回だけ**使う形で行いました。結果は、成功も失敗も、そのまま記録しています。

| 段階 | 何をしたか | 結果 |
| --- | --- | --- |
| 比較対象（v3.4 Y 系） | 価値の種類を固定した、旧来型の仕組みで、「訂正を受けた後の再学習」を評価（40 乱数、1 回） | 評価の状態を入れ替えても、学習の向きは変わらなかった。固定した価値空間の中では、目指す循環を作れないことが示された。故障は 0 件。この結果が、上の「定め直し」の根拠になった |
| 草案 4（軽い NN、評価 1 回） | 評価の学習ができる NN を使い、40 乱数で評価 | 「獲得した」とは言えない結果。ただし、**学んだ期待が初めての文脈に通用し、学習前に固定したエンコーダーより良い**ことは 40 乱数中 40 で確認できた |
| v5（評価 1 回） | 評価の状態を学習の係数として使う仕組み（wgate）を加え、別の 40 乱数で評価 | 2 つの主張が合格（下記）。ただし、片方には重要な但し書きがある |
| 重い NN（NN-REL） | 関係を扱う注意機構を使う NN を、開発用の乱数で試験 | 軽い NN と比べて、改善なし。大きく拡大する理由はない |
| v6 の予備試験 | 経歴の跡を残すための設計変更を、開発用の乱数で試験 | 後述（課題 1）。事前登録の前 |

**v5 の 2 つの合格と、その読み方**

- 主張 V1「評価の状態が、次に学ぶ中身を変える」: 合格。ただし、**この仕組みを入れていない NN でも、同じ測り方で合格する**ことが後で分かりました。つまり、この合格は、仕組みの効果ではなく、主に**測り方の性質**によるものです。「評価の状態を学習の係数に掛ければ、学ぶ中身が変わる」という、当然の効果を測っていました。
- 主張 V2「学んだ期待が初めての文脈に通用する」: 合格。これは、評価の中身ではなく、世界の仕組みの予想についての確認です。単独で人格の証拠にはなりません。

**もう 1 つの発見**: 人格ごとの「評価の状態」（どのチャンネルを、どれだけ重く見ているか）は、経歴の違いによる差が、同じ経歴の再試行の差の約 15 倍ありました。ただし、これは、結果から機械的に計算する累積の数字であり、**学習した個性ではありません**。

## 4. 課題

研究が直面している課題を、重要な順に挙げます。

1. **経歴の跡が、学習の偶然の揺れに隠れている。** 同じ経歴の人格を、学習データの順番だけ変えてやり直すと、違う経歴の人格どうしとほぼ同じだけ違います。人格どうしの違いのうち、経歴によるものは 1〜2 割ほどで、これは軽い NN でも重い NN でも変わりません。計算を増やしても、解決しません。
   - 予備試験では、「全員で共有するエンコーダー（入力を内部の表現に変える部分）と、個人ごとの頭を持ち、頭を 4 本の平均にする」設計で、経歴の効果が偶然の揺れの約 3.6 倍になりました（開発用の乱数）。ただし、効果の絶対量は小さく、事前登録の前の、事後の選択です。「個性が形成された」とは言えません。
2. **仕組みの効果と、測り方の効果を分ける必要がある。** 評価の状態が学習を変えることを、「その仕組みがあるから」と言い切れる測定を設計し直す必要があります（予備試験は、訓練の途中で状態を入れ替える方法で進めています）。
3. **評価が解釈に届く経路が、現在の世界では閉じている。** 現在の実験世界では、「いま何が起きているか」の解釈が、証拠だけで 99.9% 決まってしまい、評価が入り込む余地がありません。評価が解釈を変える様子を見るには、解釈が曖昧になる世界を作る必要があります。
4. **世界が、開発者の設計した少数の族に限られている。** 現在使っているのは、2 種類の仮想世界です。別の構造の世界で成り立つかは、未確認です。
5. **価値の種類が、嫌悪（避けたい）に限られている。** 「好きになる」という方向の価値は、まだ試していません。
6. **LLM を介した検査と、人間による評価が、未実施。**

## 5. 実験の進め方（再現性と規律）

- 判定基準を実装の前に固定し、SHA-256（ファイルの指紋）で記録します。基準は、結果を見て動かしません。変えた場合は、別の条件として記録し、元の結果も残します。
- 乱数を役割別に分けます（開発、診断、検査の腕試し、評価、予約）。評価用は、1 回だけ使います。
- 検査そのものに、わざとバグを仕込み、検出できるかを確かめます（変異テスト）。
- 設計とは別の担当が、**前提そのものを疑う批評**を、凍結の前に行います。
- 文献は、読んだ水準（全文／要旨のみ／抜粋のみ）を明記します。
- 負けた比較、通らなかった基準、誤った推論も、削除せず記録します。

## 6. 使っている技術と計算資源

- **言語・数値計算**: Python 3.12、numpy（v3.x と Y 系）、PyTorch 2.7 以降（GPU の学習器）。
- **計算資源**: 手元の GPU（NVIDIA RTX 3050、VRAM 8GB、共有）に加え、**無料枠の範囲で**、Google Colab、Kaggle、Modal の GPU を使います。無料枠を超える費用が出る操作は、人間の承認なしには行いません。別の GPU で走らせる計算は、結果が再試行の揺れの範囲で一致することを確認してから使っています。
- **メモリの制約**: GPU のメモリ（VRAM）と、PC 本体のメモリ（RAM）は、別の制約として扱っています。
- **LLM の利用**: 設計、批評、実装、文献の収集に、Claude の各モデルと、OpenCode 経由の無料モデル（DeepSeek など）を使っています。有料の API は使っていません。
- **作業管理**: git worktree による作業の分離。

- v3.x の結果は、機構の確認であり、実験結果ではありません。設計者が書いた確率表や効果表を含みます。
- 引用した文献の大半は、要旨のみ、または抜粋のみの確認です。
