# Project frontalis

経験によって人格が形成・変化する **外部ニューラルネットワーク（NPN: Neural Personality Network）** の研究です。
AI コンパニオン「ネフィア」のための、人格の学習済み状態を LLM の外に置く仕組みを調べています。

English: [README.en.md](README.en.md)

> 状況の日付: 2026-10-17。これは研究の途中経過であり、**人格形成が実証されたという主張はありません**。

## 1. 研究目的

目標は、人間らしい文章を書く AI でも、一貫したキャラクターを演じる AI でもありません。次の循環を作れるかを調べます。

1. 既存の人格が、経験を評価する。
2. その評価と経験した結果によって、人格が更新される。
3. 更新後の人格が、次の経験を以前とは異なる仕方で受け止める。
4. この循環が蓄積し、設計者が逐一指定していない固有の価値判断が形成される。

役割分担は次のとおりです。

| 部品 | 役割 |
| --- | --- |
| LLM | 認知・言語のインターフェース。自然文の意味解釈、NPN への問い合わせ、判断の言語化。交換可能 |
| NPN | 経験によって形成される評価主体。評価・選好・価値判断の傾向を保持し、経験から学習する |
| 経験記録 | 何が起きたか、当時どう解釈したか、後から何が訂正されたかの履歴 |

重要な区別が 2 つあります。

- **人格形成と人格表現は別です。** LLM が人格らしく語れたことは、NPN が人格を形成した証拠になりません。同じ LLM・同じプロンプトで NPN の状態だけを入れ替えたとき、判断が変わるかで切り分けます。
- **人格の個性と、学習機構の故障は別です。** 固執、嫌悪の持続、反証への抵抗は故障ではありません。故障と数えるのは、数値の発散、学習の飽和、無関係な価値の崩壊のような、計算機構の破綻だけです。

正本は研究思想 [`FRONTALIS_PHILOSOPHY.md`](https://github.com/sakri9616-coder/Frontalis/blob/4fecbad/FRONTALIS_PHILOSOPHY.md) です（ブランチ `claude/project-thread-1vq8ai`、固定コミット `4fecbad`）。

## 2. 現在の方針（2026-10-17 の再定義）

これまでの実装は、研究したい問題を、解きやすい別の問題へ置き換えていました。

| 本来研究したいこと | これまでの実装 |
| --- | --- |
| 何を価値とみなすかを経験から獲得する | 5 つの欲求と効果表を、開発者が定義 |
| 経験から新しい評価の観点を形成する | 固定した特徴空間でのカルマン更新 |
| 価値同士の関係も学習する | 設計済みの相互作用で処理 |
| 予想外の人格構造が形成される | 設計済みの状態と更新則の範囲で変化 |
| NN で柔軟な評価表現を獲得する | NN は信念予測の補助に留まっていた（既定の人格には NN がない） |

そこで中心課題を次のように定義し直しました。

> 経験によって、開発者が事前に指定していない評価上の特徴・関係・判断基準を獲得し、それらが次の経験の解釈と学習を変える仕組みを研究する。

- 新しい特徴を記憶しただけでなく、**未知の経験にも作用する**ことを確かめます。
- 特徴を**外す・入れ替える**と、次の解釈と学習が変わることを確かめます。
- 最小限の初期構造や信号は必要ですが、それが獲得できる価値の種類を決め切ってはいけません。
- NN の優位性は、研究目的ではなく検証対象です。線形モデルや固定の欲求モデルは、勝敗の相手ではなく**陰性対照**として置きます。NN が負けた場合も、そのまま報告します。
- 既存の v3.x の機構（下記 Y 系）は、**比較対象**として最後まで評価します。本来の研究の達成とは混同しません。

### 3.2 v3.4 Y 系（比較対象）

「訂正を新しい経験として扱い、その主観的評価が次の学習に作用するか」を、固定した価値空間の中で調べます。

- **M1**: 訂正で変わると含意される変化を、情報源の信用ともっともらしさで重み付けて吸収する。
- **M2**: 情報源の信用を、後の検証の経験から形成する。
- **M3**: 訂正で生じた罪悪感・後悔・自己正当化が、自分の解釈への信頼 τ（上下に動き、範囲が有界）を変え、次の曖昧な結果の解釈と学習を変える。
- 主判定は、効果の大きさではなく**学習の向き**です（同じ訂正から、人格ごとに異なる向きの学習が生じるか）。
- 判定基準は実装前に固定し（`SPEC-v3.4.md`）、旧基準と不合格は保存します。
- 検出力の確認として、わざと壊した 8 種の変異体を検査が検出できるかを、専用の乱数種で確かめました（8/8 検出）。
- 評価用の乱数種（40 本）は 1 回だけ使い、評価を完了しました。結果の要約は「5. 現在の進捗」にあります。

### 3.3 価値表現の獲得（本命、草案 4・改訂中）

現在は、設計草案 4 の改訂と、開発用の乱数種での較正・リハーサルの段階です。草案 4 は、独立批評の 2 回目（「現状のままでは凍結に進むべきでない」）を受けて書き直しました。草案 3.1 までの版は、`proposals/history/` と git の履歴に保存してあります。草案の骨子は次のとおりです。

- **世界**は、価値を返さず、個体の体の状態（多チャネル）の変化だけを返します。何が良いかは、人格自身の評価として形成させます。
- **生得信号**は、合算せず多チャネルのまま保ちます。恒常性（許容範囲を外れると不快）と、予測誤差・学習の進みを、同格の条件として比べます。
- **循環**を主条件に入れます。経験を受け止める時点の人格の状態から評価を作り、それが評価の頭（NN）の次の学習目標になります。
- **学習器**は、集合を扱う MLP（NN-SET）と、関係を扱う注意機構（NN-REL）です。対照に、線形、固定の欲求モデル、カーネル回帰、階層ベイズ、ランダム特徴などを置きます。
- **判定**は、正解の価値関数への近さを使いません。見るのは、経験史による分岐、循環の寄与、部分空間への介入（外す・入れ替える）の効果、評価状態の入れ替え、未知の構造への転移です。
- **LLM を介した検査**は、同じ NPN 状態を複数の LLM が受け取ったとき、主張の方向がそろうかを見ます。LLM ごとの強さや文体の差は許容し、方向が割れたときは、先に NPN の出力の豊かさを疑います。

### 3.4 検証の規律

- 判定基準・閾値・条件を実装前に固定し、結果を見て動かさない。変えた場合は別の条件として記録し、元の結果を残す。
- 乱数種を役割別に分ける（開発、診断、変異テスト、評価、予約）。評価用の種は、本番の 1 回だけ使う。
- 変異テストで、検査の検出力そのものを確かめる。
- 設計と実装とは別の担当が、**前提そのものを疑う**独立批評を行う。批評の指摘は、進行を止める条件として扱う。
- 文献は、読んだ水準（全文を読んだ／abstract のみ／開けなかった）を明記する。未確認のものを事実として書かない。

## 4. 使用技術

- **言語・数値計算**: Python 3.12、numpy（v3.x の NPN 本体と Y 系）。テストは `unittest`。
- **GPU 計算**: PyTorch 2.7（CUDA 12.8）。多数の人格を同時に学習するバッチ実装。現在の GPU は NVIDIA RTX 3050（**VRAM 8GB**、他の処理と共有）です。
- **メモリの制約（2 種類を分けて扱います）**:
  - **GPU の VRAM（8GB）**: 複数の試行を同時に走らせると CUDA out of memory が起きたため、1 本ずつ走らせ、バッチを小さくしています。
  - **ホストの RAM（32GB、共有）**: 本番規模（1 人格あたり 32,000 経験）で、データ生成の 1 工程が 11 GiB の配列を確保できず失敗しました。これは GPU の問題ではなく、データを区画に分けて生成する対応を進めています。
- **LLM の利用**: Claude Code のモデル（Opus / Sonnet / Haiku。設計・批評・実装・文献の収集）。OpenCode CLI 経由の DeepSeek v4.1 Flash（無料枠）と MiMo v2.6 Flash（無料枠。ツールを呼ばない読み手として）。有料の API は使っていません。
- **作業の管理**: git worktree による作業の分離。凍結した事前登録は SHA-256 で記録。

v3.4 Y 系（比較対象）の評価の結果は次のとおりです。

- 同じ訂正から、人格ごとに学習の向きが違う現象は一部で見られましたが、旧設計や M3 を外した条件でも同じ ERR で出たため、**M3 の寄与とは言えません**。
- **評価状態を入れ替えても、訂正の効果の向きは変わりませんでした**（類似度 0.99〜1.0）。向きを決めていたのは評価状態ではなく、信念と経験記録（何を事実と受け止めたか）でした。固定した価値空間の中では、「評価状態 → 次の学習」の循環は作れませんでした。これは、再定義の見立てと一致します。
- 自己解釈への信頼 τ の動きは小さく（|log τ| 最大 0.028）、故障（数値の発散、飽和、無関係な価値の崩壊）は見つかりませんでした。
- 誤帰属が多いときの過剰訂正は、反対側へ行く個体が 76% から 13% に減りましたが、なくなってはいません。

これまでの設計の確認で、次の否定的な結果も得ています。

- 旧設計の機構検証から、価値の符号の大半が固定されており、人格間の差が大きさ（少数の自由度）に限られていた。
- 開発用の予備検査で、経験史による分岐が、同じ経験史の再試行の雑音と同じ大きさになる場合があり、機構の改良が必要だった。
- 独立批評で、設計の主判定が、世界の生成規則を当てる課題になっている、判定の一部が自明に通る、と指摘され、設計を作り直している。

## 6. 未検証の仮説

次はすべて、まだ**支持されていない**仮説です。

1. NN は、固定した軸のモデルでは表現できない、特徴同士の相互作用を、経験から獲得する。
2. 獲得した特徴は、記憶ではなく、未知の経験（新しい文脈・組み合わせ）にも作用する。
3. 学習した特徴を外す・入れ替えると、その後の解釈と学習が変わる（特徴が実際に使われている）。
4. 経験を受け止める直前の評価状態が、次の学習の方向を変える。ただし、初期評価の自己強化に留まらない。
5. 同じ訂正を受けても、経験史の異なる人格は、異なる向きに学習する。
6. 一つの外部の永続状態が、異なる LLM にまたがって、主張の方向をそろえて働く。文献では裏付けを確認できなかった。
7. 獲得の記憶を壊さずに、消去と文脈依存の再出現を両立できる。
8. Y 系の機構（M1 吸収、M2 情報源の信用、M3 罪悪感と τ）は、人間の心理学の知見に沿う。文献との照合は未了。
9. 価値表現の獲得と転移で、NN が線形・カーネル・階層ベイズなどの対照に勝つ。**勝つことは前提にしておらず、負けた場合もそのまま報告する。**

## 7. 限界と注意

- 世界は、開発者が設計した構造の族です。結論は常に「その族での」ものに限ります。
- v3.x の結果は機構の確認であり、実験結果ではありません。設計者が書いた確率表や効果表を含みます。
- 引用した文献の大半は、abstract のみの確認です。
- 旧 Phase 3-F の数値は、v3.x の前提には使っていません。
- 人間による評価は、まだ行っていません。
- 本リポジトリの研究は、人間の精神疾患や主観的意識を再現したと主張するものではありません。

## 9. 再現

v3.x と Y 系は numpy だけで動きます（Python 3.12 で確認）。テストは次の形で実行します。

```bash
cd frontalis-v3-lab
python -B -m unittest discover -s tests -p "test_ra_mechanisms.py"
```

注意: Windows には `fork` がないため、並列実行は `spawn` 方式です。v3.3 の結果ファイルは Python 3.13 で作られており、Python 3.12 では、一部（NN 系）で数値が一致しません（最大差 0.030。版の違いの影響として記録）。
